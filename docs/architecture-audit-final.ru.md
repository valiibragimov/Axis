# Заключительный архитектурный аудит Axis

Дата: 2 ноября 2026. Проверяемый срез: `c31c1e7`, текущий main после переименования продукта в Axis. Область — восемь исходных карточек из [дорожной карты](architecture-audit-roadmap.md), а не новая спецификация продукта. Проверены исходники, история исправлений, существующие тесты и результаты новых локальных проверок. Production-данные, развёртывание и реальные счета Firebase не использовались.

## Вердикт

**Первоначальный архитектурный аудит завершён как цикл исследования, исправления подтверждённых проблем и принятия явно описанных ограничений.** Три P1 остаются закрытыми в исходной области. Новых подтверждённых критических дефектов в проверенной области не выявлено; изменений runtime-кода этот аудит не требует. Это не утверждение об отсутствии любых ошибок или о готовности к неизвестным нагрузкам.

Результат реализации по-прежнему **4 исправлены / 4 частично исправлены**. Частичные карточки 4, 5, 7 и 8 не превращаются в полностью реализованные: их оставшиеся работы условны и не являются обязательным рефакторингом для завершения исходного аудита.

## Проверка всех этапов

| Этап | Фактическая реализация и достаточность свидетельств | Решение |
| --- | --- | --- |
| 1, P1, идентичность | `control-plan/service.ts` объединяет source/registry/journal по module-scoped алиасам, проверяет отрицания до положительных статусов, связывает закрытие с исходной и отдельной успешной повторной проверкой. Smoke и браузерные тесты покрывают дубли, конфликтующие ссылки, чужой модуль, свежий отрицательный результат и legacy. Неподтверждённые старые инженерные результаты не доказывают текущую приёмку. | Исходный дефект исправлен. Сохранить регрессии. |
| 2, P1, запись | Репозиторий атомарно пишет source + registry + `inspectionSync`; проекция восстанавливается по durable pending и сравнению revision. Новая каноническая запись может обновить существующую аналитику в той же транзакции. Emulator проверяет отказ записи, потерю подтверждения, повтор, конкуренцию, доступ и восстановление после открытия. | Исходный дефект исправлен. Массовая операция атомарна по пакету, не по всему проекту. |
| 3, P1, гонки | План и сводка проверяют поколение запроса, проект и workspace перед применением результата; аналитика получает проверку актуальности. Браузерные регрессии покрывают A→B, повтор одного проекта, позднюю ошибку, busy и снятие выбора. Обзор также отбрасывает устаревшие поколения. | Исходный дефект исправлен; отмена всех сетевых запросов не требуется для этой гарантии. |
| 4, P2, чтения | Обзор повторно использует успешное чтение замечаний; сводка передаёт свои источники. Восстановления объединяются на время запроса, новые доказанные идентичности не вызывают повторных полных сканов. Бюджетные тесты и emulator защищают ревизии, alias lookup, legacy, transforms и fallback. | Подтверждённые узкие места исправлены. Остаток — стоимость update/delete, см. ниже. |
| 5, P2, BIM | Сортировка и повторный поиск оптимизированы после замеров; weak-кеш учитывает изменяемые поисковые поля. Проверены worker IFC, единицы/размещения, IndexedDB, viewer disposal; публикация защищена immutable generations, epoch/revision, leases и GC fencing. Параллельные старты объединены по UID/проекту. | Риск полного каталога документирован; нет доказательства OOM в текущем production. |
| 6, P2, сервер | Runner ограничивает историю ключей и освобождает истёкшие; HTTP disconnect отменяет очередь/разбор, но начатая фиксация завершается под lock. Worker имеет лимиты очереди, размера и времени. Shutdown запрещает новую работу и ждёт зарегистрированную. Есть реальные worker/socket и управляемые failure-тесты. | Исправлено для одного процесса; распределённая очередь не является текущим требованием. |
| 7, P3, workspace | Runtime владеет idempotent navigation-init, 22 чистых forwarding-функции удалены. Реальные браузерные тесты проверяют повтор init, lazy/coalescing, fallback после ошибки действия и journal→source в двух документах. | Подтверждённый дефект исправлен; один workspace на Document остаётся явной границей. |
| 8, P2, правила | Mandatory strict-профиль охватывает construction/registry и все четыре evaluators с зависимыми контрактами; ESLint CLI отрицательными примерами проверяет границы. Legacy reinforcement facade — реэкспорт единственного evaluator. Тесты защищают единицы, неполноту, подтипы и допуски. | Выбранная инженерная область защищена. Глобальный strict не включён намеренно. |

| 8: legacy strict:false вне выбранного профиля, ограниченный import gate | Подтверждённый технический долг; сам по себе не доказывает ошибку расчёта или утечку. ## Безопасность данных и пределы доказательств

Owner-scoped Firestore rules и emulator denial-тесты проверяют пользователей/проекты; серверные Admin adapters требуют существующей HTTP-авторизации. Это не аудит настроек реально развёрнутого Firebase. SDK retries и channel cancellation проверяются на синтетическом transport, не в пользовательском Chrome с расширениями. Исходные записи, версии критериев, исторические связи и snapshots BIM не мигрировались. Полнота старых данных не подменяется успешной текущей приёмкой.

Достаточность тестов оценивается по сценариям, а не проценту покрытия: публичные сервисы/DOM, управляемые частичные отказы и реальные правила emulator взаимно дополняются. Нет доказательства production SLA, полного mobile memory budget, распределённого drain или независимости нескольких context одного DOM. Дополнительных тестов, повторяющих неизменённую реализацию, не добавлено.

## Производительность и финальные проверки

Исторические сравнительные измерения сохранены без выдачи за новые: [аналитика](inspection-analytics.ru.md) — 100 добавлений: 100→1 полный запрос, 5 050→1 возвращённая запись (при 1 000 исходных: 105 050→1 001), point reads 300→598, alias queries 300 без изменения. [BIM](bim-catalog-performance.md) — 100k: Node sort 602→196 мс, Chrome warm search около 115→11–24 мс, heap каталога около 24→55 MiB. Это локальная синтетика, не денежная стоимость Firestore и не peak памяти процесса.

Финальные проверки: clean `npm ci` во всех трёх пакетах; typecheck (включая mandatory engineering strict), lint, build (после описанного shared:generate), `npm test` — 204 smoke + 58 core + 52 UI, без пропусков/ошибок; `audit:all` — 0 уязвимостей во всех пакетах. Независимое параллельное code-review по Standards/Spec относительно `c31c1e7` и текущего запроса: **0 / 0 замечаний**. Ревью подтвердило границы выводов, источники, численные результаты и согласованность переводов. Только синтетические fixtures/loopback emulators; локальные логи и generated drift в коммит не включаются.
